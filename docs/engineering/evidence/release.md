# ReelSaid release verification

The public repository runs on-demand release jobs and the daily check. GitHub checks out the exact approved public package and verifies that the approved private revision is reachable from the private default branch. The runner uses a read-only deploy key and removes the key before invoking the private release script. Apify CLI uploads the allowlisted Actor files, disables build-time environment variables, and starts a cached build on Apify. GitHub retains the outcome and leaves detailed build and test output on the authorized surfaces.

The daily job checks the deployed default and runs an explicitly pinned verifier revision stored as a protected repository secret. The publication operation requires the owner-approved digest of the latest effective pay-per-event schedule. It applies the exact build and listing together after a smoke test and reads the Actor back to resolve lost acknowledgements. The release suite exercises a newer free plan replacing an older paid plan and an acknowledged-by-readback publication.

Apify built `0.1.10` and `0.1.11` with caching enabled. The authorized logs each contained eight cache-hit markers. The final image size was 953,715,712 bytes. The staged build excludes generated bytecode, repository history, fixtures, and release scripts.

The rollback rehearsal created an isolated build that failed on Apify while the prior default remained available. It then selected `0.1.11` as the private default, ran the prefill, and restored the original default resolving to `0.1.9`. [Rollback rehearsal](https://github.com/aimansour/reelsaid/actions/runs/42485782758)

The Store's automated daily reliability signal is a post-publication check. This private test used the build's prefill and verified the same success and dataset conditions within the five-minute Store window. Earlier test evidence covers scheduling, resume, concurrent state, and accepted pay-per-event debits on the private billing probe. The owner deferred the final prices and the Apify icon upload. The approved 512 px icon remains in the public package and the README.
